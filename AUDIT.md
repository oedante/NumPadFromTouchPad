## 2. Архитектура старого проекта (NumMac)

Всё приложение сосредоточено в одном классе `MainWindow` (code-behind, нет разделения на слои).

- **Точка входа**: `App.xaml` → `StartupUri="View\MainWindow.xaml"`. Закрытие окна завершает приложение.
- **Трей**: `NotifyIcon` создаётся в конструкторе, иконка грузится из `.\pictures\icon.ico` — **относительно текущего каталога**, а не каталога exe. При автозапуске (cwd = `System32`) конструктор упадёт. `Tray_Icon` не освобождается в `OnClosed` → «призрачная» иконка в трее после выхода.
- **Горячая клавиша**: `RegisterHotKey(MOD_CTRL, VK_SPACE)` в `OnSourceInitialized`. Результат регистрации игнорируется (`// handle error`). `Ctrl+Space` — системное сочетание переключения IME/раскладки в ряде конфигураций Windows → частый конфликт. Сочетание не настраивается.
- **Ввод с тачпада**: `TouchpadHelper.RegisterInput` регистрирует HID-коллекцию Digitizer/Touch Pad (`UsagePage 0x0D, Usage 0x05`) с `RIDEV_INPUTSINK` — это правильный выбор API (Windows Precision Touchpad через Raw Input, без драйвера). `ParseInput` разбирает отчёт через `HidP_GetValueCaps`/`HidP_GetUsageValue`: Scan Time, Contact Count, Contact ID, X, Y.
- **Зоны клавиш**: 19 полей `System.Drawing.Rectangle Rec_*`, координаты — сырые логические единицы HID (значения по умолчанию вида `X_0 = 8600`).
- **Генерация клавиш**: `Parse_Key()` — цепочка из 18 `if (Rec_N.Contains(...)) inputSimulator.Keyboard.KeyPress(...)`.
- **Калибровка**: `Key_Click` → 10-секундный таймер; пользователь водит пальцем по зоне; сохраняется bounding box всех точек.
- **Настройки**: `Properties.Settings` (user.config в `%LocalAppData%\<company>\<exe>_Url_<hash>\<version>`).
- **Потоки**: всё в UI-потоке (WndProc + два `WinForms.Timer`). Асинхронности нет.

## 3. Архитектура нового проекта (Touchpad)

Только визуальный конструктор: сетка 8×6 ячеек по 84 px (`mainGrid`), три шаблона клавиш (1×1, 1×2, 2×1), перетаскивание копий на сетку, корзина с анимацией удаления. Нет модели данных: клавиши существуют только как `ButtonMenu` на `Canvas`; нет назначения клавиш, нет связи с координатами тачпада, нет сохранения.

Дефекты конструктора (`MainWindow.xaml.cs`):

1. `SnapToGrid` считает центр по константе `ButtonSize = 80`, поэтому клавиши 164×80 и 80×164 привязываются со сдвигом на полклетки.
2. `OnMouseLeftButtonUp`: если ячейка занята (`IsCellOccupied() == true`), ветка `else { }` пустая — `isDragging` остаётся `true`, захват мыши не снимается, клавиша «прилипает» к курсору.
3. При удалении в корзину (`AnimateToTrash`) не сбрасываются `isDragging`/`dragButton` и захват мыши.
4. Флаг `isConstruct` влияет только на перетаскивание уже размещённых клавиш; копирование шаблонов работает всегда.
5. `btnLoadConstruct`/`btnSaveConstruct` без обработчиков.
6. Размер сетки (8×6) не связан ни с размером тачпада, ни с соотношением сторон наклейки.
7. Каталог `User Control` с пробелом; `obj/` с ~1000 временных файлов попал в архив.

**Вывод**: из нового проекта переносится идея (палитра шаблонов, привязка к сетке, корзина), но не код — он завязан на визуальные элементы вместо модели данных.

## 4. Аудит повторных нажатий (главный дефект)

### 4.1. Жизненный цикл нажатия в старом коде

```
WM_INPUT → ParseInput → FingerContact = contacts[0]
   if (!Touchpad_Touch && (X>0 || Y>0)) Parse_Key(X,Y)   // KeyPress = down+up сразу; Touchpad_Touch = true
MyTimer (50 мс) → if (FingerContact.X==0 && FingerContact.Y==0) Touchpad_Touch = false
```

Логическое нажатие «разблокируется» только когда таймер увидит контакт с координатами (0,0).

### 4.2. Установленные причины (доказаны чтением кода)

| # | Причина | Где | Следствие |
|---|---|---|---|
| R1 | **Не читается Tip Switch** (Usage 0x0D/0x42). Это кнопочный usage, его нельзя получить через `HidP_GetUsageValue`, нужен `HidP_GetUsages`. Отпускание пальца в PTP передаётся отчётом с `TipSwitch=0` **и последними координатами**, а не нулями. | `TouchpadHelper.ParseInput` | Приложение не знает, когда палец поднят. После отпускания `FingerContact` хранит последние ненулевые координаты, `Touchpad_Touch` остаётся `true`, следующее касание игнорируется. |
| R2 | Разблокировка зависит от случайного появления контакта (0,0). Нули появляются только на устройствах, которые дополняют отчёт пустыми слотами, и только если `contacts[0]` окажется пустым слотом. | `MyTimer_Tick` + `ParseInput` (порядок обхода `valueCaps.OrderBy(LinkCollection)`) | Повтор «то работает, то нет» в зависимости от модели тачпада и от того, куда именно попал палец. |
| R3 | Опрос состояния таймером 50 мс вместо событий. Нули, пришедшие между тиками, перезаписываются следующим касанием. | `MyTimer` | Быстрые повторные нажатия (< 50–100 мс между касаниями) теряются. |
| R4 | `KeyPress` = нажатие и отпускание в один момент. Удержание не моделируется вообще. | `Parse_Key` | Нет удержания/автоповтора; нельзя держать Shift-зону. |
| R5 | Нет идентификации касаний: всегда `contacts[0]`, `ContactId` не используется. | `WndProc` | Второй палец меняет «текущий» контакт; мультитач неопределён. |
| R6 | `contacts[0]` без проверки длины. `ParseInput` может вернуть пустой массив (ни один контакт не собрался). | `WndProc`, обе ветки | `IndexOutOfRangeException` в оконной процедуре → аварийное завершение. |
| R7 | Отбор контактов: `break`, когда `contacts.Count >= contactCount`. В гибридном режиме PTP (контакты разнесены по нескольким отчётам, `ContactCount` только в первом, 0 — в последующих) после первого контакта цикл обрывается. | `ParseInput` | Потеря контактов на части устройств. |
| R8 | Зоны с перекрытием обрабатываются все подряд (`if` без `else`) — одно касание может дать несколько клавиш. | `Parse_Key` | Двойной ввод на границах зон. |

### 4.3. Прочие дефекты ввода/вывода

- **Квадратные зоны**: `new Rectangle(X, Y, H, H)` — ширина и высота обе берутся из `H`; `W` сохраняется, но не используется. Для «0» (широкая) и «Enter» (высокая) зона распознавания неверна. Имена перепутаны: калибровка пишет ширину в `H`, высоту в `W`.
- **Не та семантика клавиш**: `.` → `VK_OEM_COMMA` (запятая основной клавиатуры), `-` → `VK_OEM_MINUS`, `+` → `Shift+VK_OEM_PLUS` (зависит от раскладки), цифры → `VK_0..VK_9` основного ряда вместо `VK_NUMPAD0..9`. Приложения, различающие цифровой блок (Excel, игры, 1С, CAD), видят другие клавиши.
- **Подавление штатной работы тачпада не работает**: `handled = true; return 1` для `WM_INPUT` лишь пропускает `DefWindowProc` этого окна. Raw Input — пассивная копия потока; курсор, тапы и прокрутка продолжают работать в режиме NumPad. Плюс ветка `else` использует устаревший `FingerContact`.
- **Регистрация Raw Input не снимается** (`RIDEV_REMOVE` не вызывается) — после выключения режима сообщения продолжают приходить и разбираться при калибровке.
- **`ParseInput` на каждый отчёт** заново запрашивает `RIDI_PREPARSEDDATA`, `HidP_GetCaps`, `HidP_GetValueCaps` и аллоцирует 3 неуправляемых буфера — лишняя нагрузка при 100–250 отчётах/с.
- **Нормализация отсутствует**: зоны в сырых логических единицах конкретного устройства. На другом тачпаде (другой `LogicalMax`) раскладка непригодна.

### 4.4. Калибровка и настройки

- Калибровка = bounding box точек за 10 с «вождения пальцем». Включает весь промах пальца, не учитывает соседние зоны, не проверяется. После калибровки `Touch_Event = false` — режим NumPad молча выключается.
- `Save_Settings`: `int.Parse` пустого/некорректного поля → необработанное исключение.
- 156 разрозненных параметров; добавить клавишу = правка XAML, code-behind, Settings.settings в 6 местах.
- `user.config` привязан к пути и версии exe: при single-file публикации в другую папку настройки «теряются».

### 4.5. Надёжность

Нет обработки: блокировки сеанса, сна, отключения устройства, потери фокуса, ошибок `SendInput`, повторного запуска (несколько экземпляров регистрируют один хоткей). Нет журнала. Конструктор при исключении показывает `MessageBox` и пробрасывает исключение дальше.

## 5. Что сохраняем, что перерабатываем

| Часть | Решение | Обоснование |
|---|---|---|
| Raw Input + PTP-коллекция `0x0D/0x05`, `RIDEV_INPUTSINK` | **Сохранить** | Правильный и единственный штатный способ получить координаты касаний без драйвера |
| P/Invoke-структуры `TouchpadHelper` | **Сохранить**, дополнить | Корректны; добавлены `HidP_GetUsages`, `HidP_GetButtonCaps`, `RIDEV_REMOVE`, `RIDEV_DEVNOTIFY` |
| `ParseInput` | **Переработать** | R1, R5, R6, R7, кэш preparsed data, логические диапазоны для нормализации |
| `Parse_Key` / `MyTimer` / `Touchpad_Touch` | **Заменить** | Источник дефекта; заменяется конечным автоматом по Contact ID |
| `InputSimulator` | **Заменить на `SendInput`** | Устаревший пакет; нужны скан-коды и флаг extended для клавиш цифрового блока |
| `Properties.Settings` | **Заменить на JSON** | Раскладка должна быть данными, а не 156 полями |
| Палитра, `App.xaml`-стили, иконки | **Сохранить** визуальный язык (тёмная тема, жёлтый акцент) | Узнаваемость для пользователя |
| Конструктор нового проекта | **Перенести идею** | Палитра шаблонов + сетка + корзина реализованы заново поверх модели данных |

## 6. Критические технические риски

1. **Подавление курсора.** Штатного user-mode API «отдать тачпад только мне» нет. Варианты и выбор — в `PLATFORM_FEASIBILITY.md`. Требует проверки на железе.
2. **Не-PTP тачпады** (старые Synaptics/ELAN с собственным драйвером) не публикуют коллекцию `0x0D/0x05` — для них без драйвера производителя координат нет.
3. **UIPI**: `SendInput` не доставляет ввод в окна, запущенные с повышенными правами, если приложение не повышено.
4. **Secure Desktop** (UAC, экран блокировки): ввод не доставляется — это ограничение ОС.
5. **macOS**: координаты касаний в фоне доступны только через приватный `MultitouchSupport.framework`.

## 7. План исправления (выполнен в этой итерации — см. CHANGELOG.md)

1. Вынести общую логику в библиотеку `NumPad.Core` (net8.0, без Windows) — тестируема на любой ОС.
2. Конечный автомат касаний по Contact ID с явными событиями down/move/up, учётом Tip Switch и Confidence, подсчётом ссылок на клавишу, `ReleaseAll` при любом выходе.
3. Сторожевой таймер «зависшего» контакта (устройство не прислало отпускание) — восстановление, а не маскировка.
4. Нормализованные координаты устройства (0..1 по `LogicalMin/Max`) + аффинная калибровка по опорным точкам.
5. Раскладки в JSON, встроенные NUM10/NUM20/NUM30, валидация.
6. `SendInput` с VK + скан-кодом + extended.
7. Настраиваемый хоткей с сообщением о конфликте; подавление указателя через `WH_MOUSE_LL` на время касаний.
8. UI: главный экран, редактор, мастер калибровки, настройки, трей.

## 8. Что можно автоматизировать / что требует железа

**Автоматизировано** (`tests/NumPad.Core.Tests`): автомат нажатий (все 20 сценариев ТЗ), hit-testing, калибровка, валидация раскладок, сериализация профилей, разбор хоткеев, восстановление после повреждённого конфига.

**Только на реальном оборудовании**: разбор HID-отчётов конкретных тачпадов, гибридный режим отчётов, подавление курсора/тапов/жестов, поведение при сне/блокировке/отключении устройства, доставка клавиш в разные приложения (Excel, браузер, терминал), Print Screen, UIPI, macOS полностью.
