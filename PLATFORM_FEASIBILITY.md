# PLATFORM_FEASIBILITY.md — возможности и ограничения платформ

Статус пометок: **[факт]** — подтверждено документацией или кодом, работавшим у автора исходного проекта; **[гипотеза]** — требует проверки на железе, способ проверки указан.

## 1. Windows

### 1.1. Получение касаний

| Способ | Что даёт | Без драйвера | Надёжность | Вердикт |
|---|---|---|---|---|
| Сообщения мыши / `WM_POINTER` | Только курсор (относительное движение), без координат пальца на поверхности. `WM_POINTER` для тачпада приходит лишь окну под курсором в фокусе (Windows 11) | да | — | **Не подходит**: нет абсолютных координат в фоне |
| `Windows.Devices.Input` / UWP `PointerPoint` | То же, только окно в фокусе | да | — | Не подходит |
| **Raw Input, HID-коллекция Digitizer/Touch Pad (`0x0D/0x05`) + `HidP_*`** | Абсолютные X/Y каждого контакта, Contact ID, Tip Switch, Confidence, Contact Count, Scan Time; логические и физические диапазоны осей | **да** | **[факт]** коллекция обязательна для каждого Windows Precision Touchpad (PTP); с `RIDEV_INPUTSINK` отчёты приходят и в фоне. Старый проект работал на этом API | **Выбрано** |
| Прямое открытие HID (`CreateFile` + `HidD_*`) | То же | нет: устройство открыто эксклюзивно `mouhid`/PTP-стеком, чтение запрещено | — | Не подходит |
| SDK производителя (Synaptics, ELAN) | Координаты для не-PTP устройств | требует установленный драйвер производителя | SDK закрыты/сняты с поддержки | Не используется; документируется как ограничение |
| Собственный фильтр-драйвер KMDF/UMDF | Полный контроль, включая подавление | нет | подпись EV + аттестация Microsoft, риск BSOD, высокая стоимость поддержки | **Не оправдан**: ввод получаем штатно, а подавление решается в user-mode приемлемо (см. 1.3) |

**Ограничение [факт]**: тачпады, не являющиеся PTP (старые Synaptics/ELAN/ALPS с собственным драйвером, отдающие себя как обычная мышь), коллекцию `0x0D/0x05` не публикуют. Для них приложение показывает «Precision Touchpad не найден» и не притворяется работающим. `TOUCHPAD_PARAMETERS.legacyTouchpadPresent` (Windows 11 24H2+) позволяет показать точную причину.

Проверка на железе: «Диагностика» в приложении показывает список найденных PTP, диапазоны осей и живые контакты (ID, X, Y, tip, confidence).

### 1.2. Нормализация координат

Из `HIDP_VALUE_CAPS` берутся `LogicalMin/Max` и `PhysicalMin/Max` + `Units/UnitsExp` для X и Y. Координаты приводятся к `0..1`, физический размер (мм) — для соотношения сторон в редакторе. Если физические единицы не заданы (бывает), соотношение берётся из логических диапазонов и помечается «приблизительно». **[гипотеза]**: часть тачпадов имеет неактивную полосу у краёв — поэтому калибровка по опорным точкам обязательна, а не только нормализация.

### 1.3. Подавление штатной работы тачпада в режиме NumPad

Raw Input — пассивная копия потока: курсор, тапы и жесты продолжают работать. Варианты:

| Способ | Что подавляет | Цена |
|---|---|---|
| A. `WH_MOUSE_LL` (низкоуровневый хук мыши) | Любые события мыши (движение, кнопки, колесо) до их доставки | Не различает тачпад и внешнюю мышь. Решение: блокировать только пока есть активное касание тачпада и короткий хвост после отпускания (по умолчанию 350 мс — запаздывающий тап-клик). Режим «блокировать всё» — опция |
| B. `SPI_SETTOUCHPADPARAMETERS` (Windows 11 24H2+) | Отключает тап, тап-перетаскивание, двухпальцевый тап, прокрутку, масштаб — штатно, в драйвере | Меняет пользовательские настройки → приложение сохраняет исходные значения в `pending-restore.json` до изменения и восстанавливает их при выходе из режима, при завершении и при следующем запуске после сбоя. `touchpadEnabled` — только для чтения, отключить тачпад целиком нельзя |
| C. Отключение устройства через SetupAPI | Всё, включая Raw Input | Требует администратора; Raw Input тоже пропадает → режим NumPad теряет вход. **Не подходит** |
| D. Фильтр-драйвер | Всё | См. 1.1 |

**Выбрано: A + B** (B — только если доступно). Ограничения:
- **[гипотеза]** первые события движения могут прийти в хук раньше, чем Raw Input-отчёт о касании. Порядок не гарантирован документацией. Смягчение: хвост подавления и то, что PTP начинает двигать курсор только после порога смещения. Проверка: «Диагностика → Тест подавления» считает пропущенные к курсору события.
- Хук LL работает в отдельном потоке ввода со своим циклом сообщений (не в UI-потоке): если поток хука занят > `LowLevelHooksTimeout` (~1 с), Windows молча снимает хук. Обработчик только читает `volatile`-поля. Хук переустанавливается при каждом включении режима.
- Системные жесты тремя/четырьмя пальцами на Windows 11 обрабатываются стеком PTP и через B могут не отключаться **[гипотеза]**.

### 1.4. Генерация клавиш

`SendInput` с `KEYBDINPUT{wVk, wScan, dwFlags}`:
- Цифровой блок: `VK_NUMPAD0..9` + скан-коды `0x52, 0x4F, 0x50, 0x51, 0x4B, 0x4C, 0x4D, 0x47, 0x48, 0x49`; `VK_DECIMAL`/`0x53`; `VK_ADD`/`0x4E`; `VK_SUBTRACT`/`0x4A`; `VK_MULTIPLY`/`0x37`; `VK_DIVIDE`/`0x35`+extended; Numpad Enter = `VK_RETURN`/`0x1C`+**extended** (так приложения отличают его от основного Enter).
- VK задаётся явно (без `KEYEVENTF_SCANCODE`), поэтому `VK_NUMPAD7` остаётся цифрой при выключенном Num Lock. Скан-код всё равно передаётся — его видят приложения, читающие `lParam`. Опция «Учитывать Num Lock» переключает зону на навигационную клавишу (`Home` и т. п.), как настоящий цифровой блок.
- Навигация (`Home/End/PgUp/PgDn/Insert/Delete/стрелки`) — с флагом extended, иначе система трактует их как клавиши цифрового блока.
- «=» цифрового блока Mac: в PC-раскладке своего VK нет → по умолчанию вводится символ `=` через `KEYEVENTF_UNICODE` (не зависит от раскладки).
- `Print Screen`: `VK_SNAPSHOT`/`0x37`+extended. **[факт]** Windows обрабатывает его при отпускании; при включённом «Использовать PrtScn для Ножниц» откроется инструмент Ножницы — это поведение ОС.
- Комбинации (`Ctrl+C` и т. п.) — нажатие модификаторов, клавиши, отпускание в обратном порядке. **[факт]** `Ctrl+Alt+Del` и `Win+L` не могут быть сгенерированы `SendInput` (SAS защищён).
- **[факт] UIPI**: ввод не доходит до окон процессов с более высоким уровнем целостности (диспетчер задач, установщики, приложения «от администратора»). Обходы: запуск приложения от администратора (опция, не по умолчанию) или `uiAccess=true` (требует подписи и установки в `Program Files`) — документировано, не включено.
- **[факт]** На защищённом рабочем столе (UAC, экран входа) ввод не доставляется; режим NumPad при блокировке сеанса отключается автоматически.

### 1.5. Глобальный хоткей

`RegisterHotKey` + `MOD_NOREPEAT`. Если сочетание занято другим процессом, функция возвращает ошибку `ERROR_HOTKEY_ALREADY_REGISTERED` → показываем понятное сообщение и предлагаем другое. Сочетания, зарезервированные системой (`Win+L`, `Ctrl+Alt+Del`, большинство `Win+буква`), регистрировать нельзя или не следует — предупреждаем. По умолчанию: `Ctrl+Alt+N` (не `Ctrl+Space` — конфликт с IME). Защита от случайного переключения: игнор повторного срабатывания в течение 400 мс.

### 1.6. Права, установка

Приложение работает без прав администратора. Драйвер не нужен. Self-contained single-file publish не требует установленного .NET. Автозапуск — `HKCU\...\Run`.

## 2. Linux

| Задача | Способ | Ограничения |
|---|---|---|
| Касания | `/dev/input/eventN` (evdev), протокол multitouch B: `ABS_MT_SLOT`, `ABS_MT_TRACKING_ID`, `ABS_MT_POSITION_X/Y`, `ABS_MT_TOOL_TYPE` (ладонь), `SYN_REPORT`. Диапазоны и разрешение (ед./мм) — `EVIOCGABS`. **[факт]** Подходит любой тачпад с драйвером ядра, не только PTP | Чтение требует группы `input`. Протокол A (очень старые драйверы) не поддержан — сообщается явно. `SYN_DROPPED` → все касания считаются отпущенными |
| Клавиши | виртуальная клавиатура `/dev/uinput` | События идут на уровне ядра → работают в X11 и Wayland. Нужен доступ к `/dev/uinput` (правило udev). Ввод текста — только символы US-раскладки (uinput передаёт коды, а не символы) |
| Блокировка курсора | `EVIOCGRAB` на время режима NumPad: libinput/X/Wayland перестают получать касания (курсор, тапы, прокрутка) | Блокируется только тачпад — внешняя мышь работает. «Зона трекпада» (NUM10) пробрасывается через виртуальную мышь uinput с упрощённым ускорением и тапом |
| Горячая клавиша | чтение клавиатур evdev | В Wayland нет общего API глобальных сочетаний; сочетание не перехватывается — его получит и активная программа |
| Блокировка/сон | не отслеживаются | При сне чтение останавливается; сторож движка отпускает клавиши |
| Трей | Avalonia TrayIcon (StatusNotifierItem через D-Bus) | GNOME — с расширением AppIndicator |

**[гипотеза]** Ускорение проброса курсора в «зоне трекпада» уступает libinput; проверить на устройстве и при необходимости настроить коэффициенты в `PointerForwarder`.

## 3. macOS (MacBook)

Реализация на C# (`Ogneliss.NumTouch.Platform.MacOS`), без отдельного Swift-проекта: P/Invoke в системные фреймворки.


| Способ | Что даёт | Ограничения | Вердикт |
|---|---|---|---|
| `NSEvent` touches (`NSTouch`, `allowedTouchTypes = .indirect`) | Нормализованные позиции касаний | **[факт]** только окну в фокусе под курсором; в фоне — нет | Не подходит для фонового режима |
| `IOHIDManager` на устройство трекпада | Сырые HID-отчёты | **[гипотеза]** встроенный трекпад Apple Silicon отдаёт проприетарный формат; требует Input Monitoring | Резерв |
| **`MultitouchSupport.framework` (приватный)** | `MTDeviceCreateList`, `MTRegisterContactFrameCallback`: на каждый кадр — массив касаний с ID, состоянием, нормализованной позицией 0..1, размером | Приватный API: **нет Mac App Store**; распространение Developer ID + нотаризация. **[гипотеза]** работает на Apple Silicon (используется открытыми проектами, напр. OpenMultitouchSupport для macOS 13+). API может измениться в новой macOS | **Выбрано** для прототипа |
| Генерация клавиш: `CGEventCreateKeyboardEvent` + `CGEventPost` | Нажатия, включая keypad-коды (`kVK_ANSI_Keypad0` …) | Требует разрешения **Accessibility** | Выбрано |
| Подавление курсора: `CGEventTap` на mouse events | Блокировка движения/кликов | Требует Accessibility; та же эвристика «во время касания» | Выбрано |
| Хоткей: `RegisterEventHotKey` (Carbon) | Глобальное сочетание | Работает без дополнительных разрешений | Выбрано |

Статус: код собирается и приложение запускается на macOS в CI (раннер без трекпада, 0 устройств). Раскладка структуры `MTTouch`, единицы `MTDeviceGetSensorSurfaceDimensions` и блокировка курсора — **[гипотеза]**, проверяются только на MacBook. Поддержка macOS не заявляется как готовая.

## 4. Итог

- Windows: полноценная реализация без драйвера реальна для PTP-тачпадов. Главный аппаратный риск — качество подавления курсора (п. 1.3), он вынесен в настройки и диагностику.
- Linux: реализован полностью, технически даже удобнее Windows (любой тачпад, захват только тачпада); требует прав группы input.
- macOS: реален только через приватный фреймворк, вне App Store; прототип требует проверки на устройстве.
